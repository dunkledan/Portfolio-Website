PROJECT SHOWCASE

About

Escape the Labrynth is a 2D puzzle game written using the Unity Game Engine. The player is a shapeshifting character attempting to escape a laboratory. The game has 4 levels, with each of the first 3 focusing on introducing 1 or 2 specific mechanics and building on the previous levels with fairly simple puzzles and the final level combining all previous mechanics.


The player has 3 shape states, stored in an animator component for smoother animations. This code accesses determines this state when the shapeshift input is pressed. Each state also has different abilities and this function handles which is active and other relevant properties for that state.


The shooting mechanic works using a combination of 4 different classes: the player bullet and lever class. The Player handles an input to decide where to fire and which direction to fire a bullet instance. The bullet class handles its own life time and the lever class detects a bullet instance collision to open a given door using the door class to handle the properies of the door.

The climbing mechanic handles scene changes between different layers of a given level. This mechanic is used for interesting puzzles to avoid enemies or get to inaccessable sections of the game. This uses coroutine timers to determine climbing time and ensure the player does not move when climbing. The ladder class also sets the animator state machine to be in the climbing state when appropriate to handle animation and other properties of different states where appropriate.

The enemy AI in this game uses a 2D nav mesh to determine paths that enemies can walk on. There are 3 different types of enemy in the game so far including the base enemy. These enemies include a patrol behaviour, a patrol and chase behaviour, and a patrol and shoot behaviour. The patrol And enemy classes are only able to see the player with line of sight in a radius, this is achieved using raycasting between the player and enemy to make sure the line of sight is appropriately used. The patrolling behaviour uses 2 target points for the enemy to patrol between which can be expanded for as many patrol points as required.



The background tiles for this game are procedurally generated. This is done using unity rule tiles on a tile map and the perlin noise function with sample values to determine the specific tile that should be place at a given point. This was an interesting problem to solve as it was far more mathematical than most other mechanics for this project.

The camera system in this project is fairly standard using WASD to alter the Eye Centre and Up values of a camera class which GLUT uses to look at the correct position. This created a smooth sense of camera movement throughout the world, however to give more control I also implimented mouse movement to look in an appropriate direction, using some more complex mathematical formulas to calculate angles based on a 2D mouse screen position.
